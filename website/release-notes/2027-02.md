## Server and administration
- **Before you upgrade**: RabbitMQ moves from 3 to 4.2, keeping its queues and accounts. `deploy.py up` enables the feature flags of RabbitMQ 3.13 before replacing it, and stops if yours is older: deploy `rabbitmq:3.13-management` first. With the Helm chart, RabbitMQ is replaced at the upgrade.
- Upgrade the database from PostgreSQL 12, which no longer gets security fixes, to 18: add `services/db/postgres-18.yml` to your compose files and run `deploy.py upgrade-postgres`. It moves the data into a new volume, checks every table, and keeps the old one to roll back. Clients on other hosts need SCRAM password support ([upgrading PostgreSQL](/docs/backend-admin/deployment#upgrading-postgresql)).

## Documentation
- Find what to back up besides the database: the backups don't include the results, the uploaded runs, or the keys the server generated.
